# Effect 4.0.0-rc.117 API audit

**Audited:** 2026-09-22  
**Primary sources:** installed `effect@4.0.0-rc.117` (`node_modules/effect/package.json:4`), its shipped TypeScript source, and Effect's official [v3 → v4 Schema migration guide](https://github.com/Effect-TS/effect/blob/main/migration/schema.md). The existing `effect-4-api-integration.md` is prior integration context and is not duplicated here.

## Scope and result

Searched executable source and generated-code templates under `src/`, fixture `@customType` expressions, tests that consume generated code, and the public `README.md` and `CLAUDE.md`. The current generated contract uses public RC.117 APIs, including the intentionally unstable-but-exported `effect/unstable/schema` entry. No current executable/generated-template/public-contract Effect reference is invalid. The audit found three stale custom-type examples (`Schema.email()`, `Schema.positive()`, and `Schema.itemsCount(1536)`); they have been corrected to RC.117 forms in source/test examples.

`docs/research/effect-4-api-integration.md` and `docs/research/prisma-8-effect-latest.md` now carry historical/superseded-status banners. They retain retrieval-date context but are not current package contracts.

## Boundary rules confirmed by source

1. **Decoded vs. encoded:** `Type` uses semantic keys and `Encoded` uses physical keys. Built-in leaves are driver-native identities in both views, but `Schema.brand` exists only on `Type`. Kysely interfaces therefore emit physical keys explicitly while indexing semantic `Type` leaves to retain brands.
2. **Exact key optionality:** generated insert/update fields use `optionalKey`, so `{}` is valid but `{ key: undefined }` is not. `Schema.optional` is restricted to internal config/result objects where explicit `undefined` is intentional.
3. **Date boundary:** `Schema.Date` is native `Date` on the database codec boundary. ISO text requires the different `DateFromString` codec and must not be silently accepted by generated database codecs.
4. **BigInt boundary:** PostgreSQL `BigInt` uses `Schema.String`; Kysely and codec `Type`/`Encoded` values are strings with no coercion.
5. **Key mapping boundary:** applying `encodeKeys` after `VariantSchema.extract` preserves Prisma field names for consumers while physically renaming the encoded view. Every mapping must name only fields retained in that operation codec.
